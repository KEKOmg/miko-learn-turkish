# Настройка аккаунтов и облачной базы

Приложение продолжает хранить учебные данные локально в SwiftData. Supabase
добавляет регистрацию по email, вход и резервную копию основной статистики.

1. Создайте бесплатный проект на [Supabase](https://supabase.com/dashboard).
2. Откройте **SQL Editor** и по порядку выполните миграции:

   - `supabase/migrations/202608220001_create_profiles.sql`
   - `supabase/migrations/202608220002_leaderboard_read.sql`
   - `supabase/migrations/202608240003_weekly_leagues.sql`
   - `supabase/migrations/202609050001_user_lesson_progress.sql`

   Миграция `202608240003` создаёт недельные сезоны и семь лиг. Пожизненный XP
   остаётся в `profiles.xp`, а недельный XP хранится отдельно и начинается с
   нуля каждый понедельник в `00:00 UTC`. Уже зарегистрированные пользователи
   начинают первый сезон в Бирюзовой лиге, новые пользователи — в Бронзовой.
   Миграция `202609050001` добавляет завершённые уроки: ключ `(user_id,
   lesson_key)`, лучшую точность и время завершения. RLS разрешает пользователю
   читать и изменять только свои записи; удаление клиентом запрещено.
   RPC `sync_my_lesson_progress` определяет владельца через `auth.uid()`.
3. В **Project Settings → Data API** скопируйте Project URL и Publishable key.
   Для старого проекта можно использовать `anon` key. Никогда не добавляйте в
   iOS-приложение `service_role` или secret key.
4. В Xcode выберите проект **Miko → Target Miko → Build Settings**, найдите
   пользовательские параметры и задайте для Debug и Release:

   - `SUPABASE_URL` = `https://<project-ref>.supabase.co`
   - `SUPABASE_PUBLISHABLE_KEY` = ваш publishable key

5. В **Authentication → Providers → Email** оставьте Email включённым.
   Если включён **Confirm email**, после регистрации пользователь получит письмо
   и сможет войти после подтверждения адреса. Для локальной разработки эту
   проверку можно временно выключить.

Сессия хранится в iOS Keychain. Пароли приложение не сохраняет. Таблицы
защищены Row Level Security. Клиент не может напрямую изменять очки лиги:
синхронизация и переход между сезонами выполняются функциями Supabase, которые
всегда используют `auth.uid()` текущего пользователя.

Локальный профиль авторизованного пользователя имеет тот же UUID, что и
Supabase user. При logout приложение переключается на отдельный гостевой
профиль; кэши аккаунтов сохраняются отдельно. Гостевой прогресс автоматически
не переносится в аккаунт.

Синхронизируются только завершённые уроки, без незавершённых упражнений.
Завершённость объединяется по lesson key, точность и время завершения — через
`max`. Положение курса и доступность A2 вычисляются из завершённых уроков.
Восстановление записывает прогресс напрямую, без повторной выдачи XP, gems,
дневных наград или weekly XP. Оно не вызывает completion/reward flow.

Переход сезона выполняется лениво при первой синхронизации или загрузке
рейтинга после понедельника. Для строго автоматического закрытия ровно в
полночь можно дополнительно создать еженедельную задачу Supabase Cron с SQL:

```sql
select public.rollover_league_seasons();
```

## Проверка progress RLS на временных аккаунтах

Для проверки используйте отдельный проект Supabase и разные тестовые аккаунты.
Убедитесь, что каждый пользователь видит только свой прогресс и что
повторное восстановление завершённых уроков не начисляет XP.
